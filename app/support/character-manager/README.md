# キャラクター管理

入口は [app/character-manager.html](../../character-manager.html) の1つ。正式画像・参考デザイン・制作メモと、過去の全バージョンの履歴をタブで切り替える。各候補から同じ一族の反対側のタブへ移動できる。検索・絞込・比較チェック・入力中のメモ・表示位置はタブ切替で保持する。

旧 app/compare.html と app/wildwordopia-history.html は不要。管理画面はそれらを読み込まず、iframeや別の独立HTMLにも依存しない。必要な画面断片・スクリプト・CSSをsupportから同じ文書へ初期化する。新しいcmd/bat/ps1ランチャーは追加しない。

保存キーと採用判定、メモの復元・書き出しの処理は維持する。保存データの消去・自動結合は行わない。ただし file:// の保存領域はブラウザーによってファイルURLごとに分かれ得るため、新しいファイル名から旧ファイルURLの状態を読める保証はない。HTTPでは同じブラウザー・originの保存キーを使用する。file://、別ポート、別ホスト名への切替でも保存領域は異なり得る。旧URLの保存領域そのものは変更・削除していない。

## APIを使う機能

HTMLを直接開くと、比較と全履歴の索引・画像を閲覧できる。プロンプト・造形設定などの詳細取得、履歴の再取得、エクスプローラーで保存場所を選択する機能には既存の8964番ローカル履歴APIが必要。APIがなくても索引の全メタデータを詳細欄で確認できる。APIのための新しい起動ファイルは作らない。

既存サーバーのHTTP入口は http://127.0.0.1:8964/character-manager.html 。旧HTTPパスはサーバー側の転送として受けるが、旧HTMLファイルは作らない。既存プロセスは停止・再起動していない。

## 更新

既存の制作側比較HTMLを取り込む限定処理：

~~~powershell
python app/support/character-manager/build.py --comparison work/wildwordopia/sample/exploration-20261014/compare.html
~~~

画像・辞書・履歴を生成する処理ではない。元HTMLから文書タグを除いて画面断片を取り出し、CSSとJSを同じ文書用モジュールに分離する。候補の本文や元の画像を変更しない。元HTMLの構造が想定外なら停止する。旧2HTMLは再作成しない。

production/publish_review_ui.py の比較出力も install_comparison() を呼ぶ。ユーザーが移動した app/wildwordopia.html が存在しない現状では、広範囲な公開用生成処理は最初に停止する。この統合のために公開用生成処理を実行しない。履歴の元データの出力先 app/support/wildwordopia-history/wildwordopia-history-data.js は変更しない。

履歴の表示断片は history-template.html、CSSは history.css。断片を変更した場合は引数なしで build.py を実行する。独立したHTML入口は出力しない。

## 正式画像をブラウザー間で共有する

「選択した正式画像を共通ファイルへ保存」は、選択をこのブラウザーに残したうえで、共通選択ファイルの保存を開く。保存先は **`app/support/character-manager/site-image-selections.js`**。既存の同名ファイルを指定する。画像本体・候補台帳・メモ・採否・削除履歴は変更しない。共通ファイルに含めるのは一族ID、選択した候補ID、プロジェクト内PNGへの相対パス、日時だけ。

以前Chromeで「サイトへ反映」していた選択を移す場合は、**そのChromeで管理画面を再読み込みし、「このブラウザーの反映済み画像を共通保存」を一度押す**。この操作は保存済み `wildwordopia.manager-published.v1` を使い、最新画像を自動的に選び直さない。保存できたら、別ブラウザーで同じ `app/wild-wordopia.html` を開き直す。新しいブラウザーにメモや採否をコピーする操作ではない。

共通保存は完全な自動保存ではない。♥だけではブラウザー内の仮選択にとどまる。「選択した正式画像を共通ファイルへ保存」を押すと保存ダイアログを開き、対応ブラウザーでも **毎回** 上記共通JSへの保存確定が必要。保存先ハンドルや書込み権限を保持する実装・保存API・バックグラウンドでのファイル書込みはない。writeとcloseの成功後にだけ書込み完了として扱うが、選んだ保存先が指定のパスだったかは検証できない。file表示・HTTP表示ともこの条件は同じ。

保存ダイアログに対応しないブラウザーでは同名JSをダウンロードする。ダウンロードを開始しただけでは共通反映完了にしない。保存したファイルを上記の場所へ手動で置き換える。キャンセル・書込み失敗時もブラウザー内の選択・履歴は残る。ファイル選択画面で違う場所へ保存した場合は、そのファイルを上記の場所へ移す必要がある。

Wildは共通選択と最新正式画像のmanifestを最初の表示から読む。古い `manager-published.v1` の日時だけでは、現在の正式画像や共通選択を上書きしない。既存キー・バックアップ・旧履歴は消去しない。旧ローカル記録しかない一族では従来値を使える。新UIの明示選択は `selectionMode: explicit` と `selectedAt`、自動選択は `selectionMode: automatic` と候補の `updatedAt` を分けて保存する。共有された明示選択は過去版を意図的に選んだ場合も保持する。新しい明示ローカルプレビューは現在の判断より新しい場合だけそのブラウザーで使い、他ブラウザーへ渡すには共通保存する。自動選択は新しい正式画像へ追従する。

`build-latest-site-images.cjs` は比較一覧をブラウザーなしで読み、選択中の正式画像と一覧内のPNGのSHA-256・実ファイル更新日時をmanifestへ記録する。通常の `--check` は読取りだけ。候補ID・パスの変化がある新画像の登録時は内容を確認して `node app/support/character-manager/build-latest-site-images.cjs --accept-choice-changes` を使う。既存画像の同じパスの内容更新では通常のコマンドを使える。PNG自体・辞書・ユーザーの選択は変更しない。入口と生成テンプレートのmanifest参照も安定した内容版に合わせる。

画像URLは `?v=<PNGのSHA-256>` で版を示す。毎回の起動時刻は使わず、内容が同じなら同じURLになる。過去版を明示選択した場合も、一覧にある同じ画像ファイルの中身が更新されれば新しいハッシュを使う。更新後は通常のページ再読込で新しいmanifestを読む。ブラウザー全体のキャッシュや保存データの消去は不要。

PNGは複製・加工せず参照する。別PCへ持ち運ぶ場合は、選択ファイルだけでなく参照先のPNGも同じ相対位置に必要。ローカル `work/image/` の画像を選べても、そのことは画像や制作資料を公開してよいという意味ではない。公開用生成やGit操作はこの保存処理に含まれない。

既存8964サーバーの静的許可リストも新しい選択モジュールに対応。稼働中プロセスはこの修正で再起動していない。HTTP入口から使う場合、既存サーバーの管理者による通常の再起動後に許可が反映される。file表示にはサーバー不要。HTTPから `file:` の画像を読む制限があるため、ローカルファイル画像の選択と共有は同じfile入口で確認する。

追加検証：`node app/support/character-manager/site-images.test.cjs` と `python app/support/character-manager/test_server_routes.py`。独立した2つの保存状態を持つメモリ環境と静的経路を確認し、実ブラウザー間同期や利用者の実保存を実行するテストではない。

## 検証

~~~powershell
node app/support/character-manager/test_manager.cjs
~~~

メモリー上のDOMモデルで、単一文書のモジュール初期化、タブ・一族の移動、履歴の検索・絞込・比較チェック・ページ送り・詳細のオフライン表示、スコープ付きDOM参照、旧HTMLと追加ランチャーの不在、全ローカル依存の存在を確認する。ブラウザー描画・画像読込・file:// の保存実装・稼働APIを確認するテストではない。利用者の実データで採用・メモ・削除の操作を試験しない。

統合時の一致確認：比較669候補・214語根、参考リンク3,844件（697種類）。全履歴2,304件・216語根（候補1,388件、途中版916件）。履歴の日付あり記録は2026-10-09〜2026-10-21、日付なし17件。genu1 と未登録試作も保持する。比較の全article本文と画像・リンク参照、履歴データのバイトハッシュは統合前と一致。

編集前記録は work/character-manager-20261028/。この実行環境ではブラウザーのfile URLがURLポリシーで拒否され、8964番APIの読み取りもソケット権限で拒否された。迂回・再試行を行っておらず、実ブラウザーと稼働APIの確認は残る。
