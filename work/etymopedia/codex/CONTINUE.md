# 稼働中Codexへの継続指示

現在の画像生成を、先頭へ戻さず続けてください。共通の仕様は [WORKFLOW.md](../WORKFLOW.md)、追加列の見本は [prompt_rows_template.csv](../etymopedia_sample/prompt_rows_template.csv) です。

1. 今使っている担当CSV・現在行・保存済みPNG・生成要求との対応記録を確認する。過去の進捗報告やCSV番号だけで未着手を判定しない
2. 安全な保存境界で、自分のCSVの末尾へ不足列だけ追加する。既存7列・既存値・行順・未知の追加列・正式画像名を保持する。読込処理が列数固定なら列名読込へ対応させ、移行前後の既存値を検証する。他の担当者のCSVは編集しない
3. 各行について、正本の正確な見出し語・順序付き語根ID・第一語義・正式画像名を確認する。対応や語義が古い行は保留し、絵に合わせて第一語義を変えない
4. 1行につき1画像を生成し、行キーと返却結果の対応を保存する。担当1の案は `画像生成プロンプト` に保持し、実際に送った全文を `実行プロンプト` に保存する。構図を修正して生成した場合も必ずCSVへ残す
5. 実PNGを検品し、その絵と第一語義に合う `解説英語`・`解説日本語` を書く。英語は通常6〜14語程度を目安、上限18語、最低語数なし。単純な物は自然な短い句でもよい。見出し語の正確な形を含め、`This is X.` の量産・水増し・見えない筋書きを避ける。日本語も同じ場面を短く自然に表し、本文に「イラスト解説」等のラベルを入れない
6. 主役＋具体的な特徴／行動／関係が必要十分か、英日は同じ内容か、長い重複や情報不足がないかを全件確認する。画像だけで単語を一意に当てられることは合格条件にしない
7. 生成しただけなら `generated`、実画像・解説・数値仕様の検品合格後に両画像ハッシュ・検品日時・根拠を保存して `reviewed`。問題は `needs_revision` または `error` と原因を残す。1件ずつ安全にCSVを保存する
8. 既存画像で解説だけが欠けている場合は実物確認後に補う。過去の実行プロンプトが不明なら空欄と理由を残し、画像を見て逆算しない。新規生成と区別し、画像を不要に再生成しない
9. 更新済みCSVと合格PNGを反映担当へ渡す。`applied` は原本保存の確認後のみ。専用CSV取り込みコマンドはまだ未実装なので、存在すると仮定して実行しない

白・濃紺・ピンク背景で透過と縁を確認し、512×512 PNG・RGBA・実アルファ、1画像1構図、唯一の画風参照、文字・ラベル禁止などの既存規則を守る。画像名・保存先は変更しない。
