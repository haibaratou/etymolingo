## 1. ゲームの核（変えてはいけないこと）

- 漢字のタイピング・ローグライク（Glyphica＋Vampire Survivors）。敵も味方も漢字。
- 敵の字の下に出る英単語を打つと、その字の**部品が一つ剥がれる**（休→木、海→水）。
- 主人公は字（既定は「人」）。**主人公は進化しない。**
- **仲間は作字台（Tab）でだけ作る。** 倒した敵の魂（字）を部品にして、実在する組み立ての字を作る。
  - 仲間になれるのは部品が二つ以上の字だけ。一字の字（川・犬…）は材料にしかならない。
  - 主人公の字は箱に ∞ 入っている（使い放題）。ほかの魂は使うと減る。
  - 主人公の字＋主人公の字だけでは作れない（人＋人＝从を無料で作らせない）。
- **レベルアップは命+1だけ。** 昔あった三択（字魂転生）は廃止。復活させないこと。
- 合体レシピは捏造しない。字典（`data/kanji_db.json`）にある組み立てだけを使う。
- 対応言語は今後増やす予定。**英単語の長さや画数をゲームの数値に使わない。**

## 2. 確定した仕様（ユーザーが決めたこと）

### 敵
- **敵はみな HP バーを持つ。** タイピング以外の攻撃（仲間の技など）は HP を削るだけ。HP が 0 になると**部品が一つ剥がれる**（字が丸ごと消えるわけではない）。タイピング以外で字そのものを削ると爽快感が減るため。
- HP は**敵の格**で決める（`data/game.json` の `RANK` と `RANK_HP [3,3,6,12,24,40]`）。字の長さや画数では決めない。
- 字が壊れるときは**部首が残る**（蛇→虫、海→水、休→人）。
- **敵の動きは部首で決まる**（`game.json` の `RAD_BEH`）。人は逃げる、水はその場に留まる、牛馬は突進、犬は速い、鳥は飛ぶ、虫はジグザグ、鬼は瞬間移動、風は渦、土は潜る、弓矢は距離をとる。このルールは徹底すること。
- 蛇は長い列で来る。頭を打つと、列ごと連鎖で壊れて虫になり、虫がバラバラに襲ってくる。
- 敵の群れは行列ではなく、ばらばらに襲ってくる。
- 火の敵は自分の字を火の玉にして撃つ。火の玉は落ちた所でしばらく燃えて当たり判定を残し、やがて消える。
- 闇は同時に1体だけ。明るい仲間（日・月・光・火・白の部首、または光・炎の系統）がいなければ、画面全体が暗闇になる。闇の英単語のラベルはいつも見えるようにする（見えないと倒せない）。
- 福の字は画面の中で消えない。去るときは画面の外へ歩いて出ていく。**何であれ、画面の中で急に消すのは禁止。**

### 仲間
- **字の部首が「効果と色」、字の意味（英語）が「動き」** を決める（`scripts/kraft.gd`）。
- **初期の段階で敵を追尾しない。** 最初はシンプルに、強化（Lv）すると派手にする。
  - 例「日」: 主人公の頭上に字が昇り、2秒ごとにまわりへ光の結界を張る。Lv2 から、向いている方へ光線を撃つ（Lv ごとに1本増える）。
- **バリア系（水・守る・灯・結界・壁・波紋）は敵を押し返さない。** 押し返すと敵が近寄れず、無敵になってしまう。
- 火の仲間は、ヴァンサバのように**主人公の前へ**火を放つ。当たった所でしばらく燃え続ける。主人公のまわりを回すのは不可。
- 木の仲間は、まわりに木を植える壁。レーザーのような光線は出さない。
- 主人公の字は勝手に弾を撃たない。
- 自動戦闘（F6）でも、時間がたてば作字台で合体する。

### 音
- 仲間の自動攻撃の音は控えめにする。同じ音は 0.6 秒に1回まで（`ksfx()`）。口・言・音の「響く」は無音にした。**鳴り続けて不快な音は絶対に入れない。**

### 見た目
- 甲骨文字の描画は元のデータに戻した（`scripts/oracle.gd` / `data/jgw.json`）。作り直したものは「ひどい」と却下された。描き直すなら、必ずユーザーに見せて確認してから入れること。

## 3. ユーザーが嫌ったもの（二度とやらない）

| やったこと | 反応・理由 |
|---|---|
| 木の仲間が緑の光線を放つ | 「なんで木がレーザー放つんだ」 |
| 口の仲間が攻撃のたびにゴーンと鳴る | 「イライラする不快なSE」 |
| 何かわからない紫の粒 | 「なんだその紫のゴミは」 |
| 意味のわからない飛び道具（灯が飛び込んでくる等） | 「まったく意味がわからん」 |
| バリアが敵を押し返す | 無敵になる |
| 画面の中で敵が急に消える | 「画面内で消えるな」 |
| HP を英単語の長さ・画数で決める | 多言語対応と矛盾。格で決める |
| レベルアップの三択 | 作字台に一本化した |
| 意味のないギミック（蛇の毒の跡など） | 楽しさはタイピングと作字に集める |

**原則:** 字の意味から見て「なぜそう動くか」が一目でわかるものだけを入れる。理由を説明できない派手さは要らない。

## 4. 起動とテスト

### Windows（ユーザーの環境）
- `ゲームを開始.cmd` … 普通に遊ぶ
- `自動戦闘で観る.cmd` … 自動戦闘（`--watch`）
- `テストを実行.cmd` … ヘッドレスで240秒の自動戦闘
- Godot の場所は `tools/launch_godot.ps1` が探す。

### ゲーム内のキー
- Tab 作字台 ／ F6 自動戦闘 ／ F5 どこからでも再起動 ／ F7 音楽の入／切 ／ Esc 一時停止
- 起動画面の「字の試験場」: 好きな字をその場で仲間にして試す。矢印キーで移動、＋／− で Lv、PageUp/Down またはクリックで字を選ぶ。1〜5 で場面、F4 で合体の演出。移動・Lv の変更では敵や仲間を作り直さない。

### コマンドライン（`godot --path . -- <フラグ>`）
| フラグ | 中身 |
|---|---|
| `--kl --klch=晴,明 --kllv=3 --klsc=0 --klwait=8` | 字の試験場を、字・Lv・場面を決めて開く。結果を `[kl]` で出す |
| `--shots=<フォルダ> --every=0.25 --quit=10` | 0.25秒ごとに画面を保存して10秒で終了（画面がある実行のみ） |
| `--fusetest=獲,明,朧` | 合体の演出を順に見る |
| `--kcraft=犬,草,隹,又` | 部品三つ・四つの作字を試す |
| `--craft` | 遊びを始めて作字台を開く |
| `--lab` | 相性の試験場（古い試験場。F1 で表示を切替） |
| `--auto` / `--watch` / `--hero=木` / `--idle` | 自動戦闘・主人公の字・放置 |
| `--snake` `--firetest` `--yami` `--behtest` | 蛇の列・火の敵・闇・部首の動き |
| `--introshots=1,5 --shotdir=…` | オープニングの静止画 |

ヘッドレス（`--headless --fixed-fps 30`）では画像保存は失敗する（`Parameter "t" is null` などはテスト時だけのエラーで無害）。画面を撮るときは画面のある環境で、`--rendering-driver opengl3` を付けて実行する。

### 全字の性能一覧（検証の出発点）
```
godot --headless --path . --script res://tools/dump_kraft.gd -- kraft_dump.tsv
```
字・英語・日本語の意味・本体の系統・技・動き・効果・部首・部品・能力値（P A R C D X KN）を TSV に書き出す。

## 5. 仲間の仕組み（コードの地図）

### データ
- `data/kanji_db.json`（約3,166字）: `K[字] = {en, jp, stk, b(系統), s(能力値), lv(葉まで分解した素), op(部品), rad, ally, src, via(効果をくれた部首)}`、`REC["A+B"] = [できる字]`、`FAM`（12系統と、その素）、`NORM`（氵→水 など）。
  - 作り直し: `tools/build_kraft_db.py`（CHISE IDS＋KANJIDIC2）→ `tools/add_radicals.py`（部首・ally・能力値の補正）
- `data/game.json`: 敵の格 `RANK`/`RANK_HP`、部首ごとの敵の動き `RAD_BEH`、敵の構成 `COMP`、英語 `EN` など。

### `scripts/kraft.gd`（字の性能を決める）
- `prof(ch, lv)` … 性能。`kind`（系統の技）、`motion`（意味の動き）、`eff`（部首の効果）、`col`（部首の色）、能力値 `P`（一撃）・`A`（広さ倍）・`R`（速さ倍）・`C`（数）・`D`（持続倍）・`X`（貫通）・`KN`（押し）。
- `motion_of(ch)` の優先順: `MOTION_CH`（字ごとの指定）→ 龍を含む字は dragon → `MOTION_EN`（英語の意味の語）→ `RAD_MOTION`（部首）→ なし（系統の技 `BODY` を使う）。
- `RAD_EFFECT`（部首ごとの当たり方: bite・claw・peck・sting・bubble・trample・horn）、`EFFECT_JP`（系統ごとの効果）、`RAD_COL`（部首の色）。
- 説明文: `MOTION_JP`（動き）、`BODY`（系統の技）。**技を変えたら説明文も必ず直す**（試験場と作字台に出る）。

### `scripts/main.gd`（約1万行。行番号は目安）
| 関数 | 役割 |
|---|---|
| `kraft_add` (~5464) | 仲間を場に出す。`KU` に入る。同じ字なら `lv += 1` |
| `k_is_body` / `K_BODY_MOTION` (~5512) | 字そのものが場に出て動く技か、主人公から撃つ技か |
| `_k_run` (~5704) | 技の振り分け。`pr.motion` が先、なければ `pr.kind` |
| `_m_<動き>` (~5923〜6256) | 動きごとの処理: lamp dragon slash laser garlic river scatter frost annihilate rampage spread fall guard flow orbit burst bind shoot |
| `_k_<系統>` (~6268〜6467) | 系統の技: ripple trail tree orbit blade arrow shout beast slam aura throw wall |
| `k_targets(p, r, n)` | 近い順の敵 |
| `k_hit` / `_k_eff_hit` | 当てる（HP を削る・部首の効果・押し）。**押しは kn 引数。バリア系は 0** |
| `KFX` / `_k_fx` (~6475) / `_k_alive` (~6643) / `_draw_kraft` (~6664) | エフェクトの配列 → 毎フレームの更新 → 生存判定 → 描画。新しい種類は3か所すべてに足す |
| `_k_eff_draw` (~5790) | 部首・系統の効果の見た目（炎・波・樹・光・刃・矢・声・claw・peck・sting・bubble・horn・bite・岩・霊・門） |
| `ksfx(name, vol, pitch)` | 仲間の音（間引き・音量控えめ）。仲間の技では `sfx.play` を直接使わない |
| `hero.last_dir` / `hero.face` | 向き。前へ撃つ技はこれを使い、敵を狙わない |
| `eat_letter` / `break_part` / `hp_of` | 敵の HP と部品の剥がれ |
| `start_kl` / `KL_SC` (~6897) | 字の試験場 |
| `art(name)` (~685) | `assets/art/<name>.png` を読む（キャッシュ付き） |

### 新しい動きを足す手順
1. `kraft.gd`: `MOTION_JP` に説明を書き、`MOTION_CH`（字の指定）・`MOTION_EN`（英語の語）・`RAD_MOTION`（部首）のどれかで字に割り当てる。
2. `main.gd`: `_m_<名前>(u, dt, hp0)` を書き、`_k_run` の振り分けに1行足す。字が場に出るなら `K_BODY_MOTION` にも入れる（`u.free = true` にして `u.x/u.y` を自分で動かす）。
3. エフェクトは `KFX.append({"k": "<種類>", "u": u, ...})`。`_k_fx`（更新）・`_k_alive`（寿命）・`_draw_kraft`（描画）に足す。
4. 強化は `u.lv`（同じ字を重ねた数）で分ける。**Lv1 は控えめ・狙わない、Lv2 以上で派手に。**
5. `--kl --klch=<字> --kllv=1` と `--kllv=3` で撮って見比べる。

### 検証のやり方（提案）
1. `dump_kraft.gd` で一覧を出す。
2. 技ごと・部首ごとに代表字を選び、`--kl --klch=<字> --kllv=1/3 --shots=…` で撮る。
3. 次の観点で判定し、表にする（字・今の技・判定・直し方）:
   - 字の意味と動きが合っているか（英語の意味が誤って拾われていないか。例: `MOTION_EN` の語が別の意味に当たる）
   - Lv1 で敵を追尾していないか
   - 画面の中で急に消えるものがないか
   - 音がうるさくないか
   - 何が起きているか、1秒見てわかるか
   - 重くないか（敵が多い場面 `--klsc=4`）
4. 汎用の技の字から、**よく出る字・意味がはっきりした字**を優先して、専用の動き（`MOTION_CH`）や新しい動きを作る。数千字を一つずつ作るのではなく、意味の群（休む・付ける・討つ・伏せる・変わる…）ごとに動きを作って割り当てる。
5. 変えたら README の「仲間の字」の節と `MOTION_JP` を直す。

## 7. 水墨画アートの現状と方針

### すでにあるもの
- 生成の指示書: `art/CODEX_ART_TASK.md`（以前 Codex が画像生成で作った。原画は `art/incoming/`）。
- 取り込み済み（白地を透明にしたもの）: `assets/art/`
  - `blot0-8`（墨溜まり）、`splash0-8`・`splashw0-8`（しぶき）、`stroke0-3`（斬撃の筆）、`cloud0-3`（雲）、`net`（網）
  - `scene_*`（漢詩の景色10枚）、`monster_*`（渾沌・蚩尤・饕餮と、その光輪）、`title_landscape`
- 使っている所: 敵を倒したときの墨の染み（`tex_stain`）、斬撃（`tex_stroke`）、雨雲（`cloud2`）、決戦の怪物、漢詩の景色。
- **仲間の技のエフェクト（`_k_eff_draw` と `_draw_kraft`）は、まだほとんどが線と円をコードで描いたもの。** ここを水墨画にするのが本題。

### 取り込みの道具
```
python tools/ink_import.py art/incoming/fx_ink_splash.png splash --split 9
```
白地を透明にして `assets/art/` に保存する。`--split N` で、つながった墨のかたまりを N 個に切り分ける（`splash0..8.png`）。`--keepcolor` で淡彩を残す。`--max` で長辺の上限。

### 画像生成のルール（`art/CODEX_ART_TASK.md` と同じ）
- 必ず画像生成モデルで描く。コード（SVG・PIL など）で絵を描いて代わりにしない。
- 本物の東洋の水墨画（濃墨・淡墨・破墨・潑墨、滲み、かすれ）。色は朱・黄土などの淡彩を控えめに。
- 背景は真っ白（#FFFFFF）。和紙の質感や影は付けない（あとで透明にするため）。
- 文字・落款・印・枠は入れない。写実3D・アニメ調・フラットは不可。
- 原画は `art/incoming/` に。既存ファイルは上書きしない。

### 作るとよい素材（候補）
仲間の効果ごとに、白地に間隔をあけて並べた「素材シート」を作り、`--split` で切り出す。
- 炎: 筆で描いた炎の舌（3×3）、燃えさし、火の粉
- 水: 墨の波紋の輪（同心円が滲んで崩れるもの）、水しぶき、泡
- 光: 淡墨の地に白く抜けた光芒（放射の筆）、日輪
- 木: 枝・根・葉の一筆
- 刃: 太い一閃（今の stroke を増やす）、交差の斬撃
- 獣: 爪痕三本、噛み跡、足跡
- 鳥: 羽、ついばみの点描
- 岩: 割れた岩の塊、土煙
- 霊: 霞の帯、鬼火
- 糸・網: 絡みつく糸、結び目
- 声: 音の波を表す筆の弧
描画では、テクスチャを `ci.draw_texture_rect` で置き、回転・拡大・アルファで動かす（`glow()` と同じやり方）。加算ではなく、紙に墨が乗る見た目（通常合成・墨色）を基本に。光と炎だけ明るくしてよい。

### 注意
- 1枚生成するごとに保存し、ゲームの画面で見て確かめてから次へ。
- 重さに気をつける（テクスチャは長辺512px程度まで。同じテクスチャを使い回す）。
- 甲骨文字の線（`oracle.gd`）は画像に置き換えない（ユーザーが元の線を良しとしている）。
