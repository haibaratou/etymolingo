KANJI SURVIVOR（仮）
Claude向け企画・プロトタイプ引継ぎメモ
更新: 2026-10-06

============================================================
0. 一言でいうと
============================================================

Glyphica: Typing Survival のミニマムなタイピング・サバイバルを土台に、
「漢字・象形文字そのものが敵であり味方でもある」ゲーム。

文字の反乱を、文字で制する。

主人公は「人」の古い象形文字。
敵も味方も漢字。
文字は実在する構成関係に従って合体・進化し、
攻撃を受けると構成要素へ分解されて弱体化する。

単なる
「漢字に攻撃力・HPを付けたゲーム」
ではなく、
「漢字の意味・構造・成立・配置が、そのままゲームルールになる」
ことを最優先する。


============================================================
1. プロトタイプの基本メカニクス
============================================================

参考:
Glyphica: Typing Survival

ただしコピーではなく、
画面・演出・進化システムを漢字そのものに置き換える。

基本ループ:

1. 四方から文字の敵が押し寄せる
2. 対象の読み・意味・英語などをタイプして攻撃
3. 敵文字の構成要素が壊れ、別の文字へ変化
4. 敵を倒して素材となる文字を得る
5. 味方文字を実在する構成関係で合体
6. 新しい文字へ進化
7. 進化後の「意味」が能力そのものになる
8. ボス戦では熟語・成句・漢詩など、より大きい言語単位へ進む


============================================================
2. 最重要ルール
============================================================

合体レシピを捏造しない。

採用基準:

A. 実際の古文字・字源として成立する
B. 実際の漢字構成として成立する
C. 形声文字でもよい
   「意味＋意味」になっている必要はない
D. 中国語を知っていると形声系列を予測できるなど、
   言語知識がそのままプレイヤースキルになってよい

不採用:
「見た目がそう見えるだけ」で歴史的・構造的根拠がない偽レシピ。

例:
現代字体の「会」を
人 + 云 → 会
と機械的に作るだけなら、字源としては偽。
こういうものを正式レシピにはしない。


============================================================
3. 主人公「人」の進化
============================================================

主人公は現代漢字の「人」ではなく、
古代の「人」の象形文字をベースにする。

重要:
同じ「人」×2でも、
配置・向きによって結果が変わり得る。

例:

人 + 人（前後に従う配置）
→ 从
「したがう」

人 + 人（並ぶ）
→ 比
「ならぶ・くらべる」

人 + 人（背中合わせ）
→ 北
古字では「背を向ける」形。
後に方角の「北」に転用された。

人 + 反転した人
→ 化
「かわる・ばける」

つまりレシピは
素材A + 素材B
だけでなく、

素材 + 配置 + 向き

を持てる。

SVGアニメーションなら、
本当に人の象形文字を移動・反転して合体させる。


============================================================
4. 「化」ルート
============================================================

人
→ 反転した人と合体
→ 化

化から分岐:

化 + 艹（草）
→ 花

化 + 貝
→ 貨 / 货

化 + 革
→ 靴

化 + 言
→ 訛 / 讹

重要:
花・貨・靴などは、
「化」の意味を足して作る会意文字とは限らない。
形声文字も含む。

それでよい。
中国語を知っていれば音符の関係を読めるため、
知識が攻略上の有利になる。


============================================================
5. 「花」以降
============================================================

花 + 木
→ 椛
日本の国字。「もみじ」

花 + 米
→ 糀
日本の国字。「こうじ」

このように
共通の古代文字体系
↓
中国系進化
日本系進化
台湾・香港系字体
などへ地域分岐してもよい。

region例:
ANCIENT
COMMON
CHINA
JAPAN
HK_TW


============================================================
6. 「休」ルート
============================================================

人 + 木
→ 休

意味:
人が木に寄りかかる / 木のそばで休む古字形。

ゲーム性能:
「休む」という意味をそのまま能力にする。

例:
・静止中にHP回復
・攻撃しない時間が長いほどチャージ
・休止解除時に蓄積した力を放出

さらに構造上は
休を部品として持つ文字も存在する。

例:
口 + 休 → 咻
广 + 休 → 庥
豸 + 休 → 貅
髟 + 休 → 髹
など

ただし、
ゲーム採用時は「字源・意味・使用頻度」を確認してから使う。


============================================================
7. 「付」ルート
============================================================

人 + 手（古字形）
→ 付

後世では手の部分が「寸」に近い形になる。

付から:

付 + 广
→ 府

府 + 肉
→ 腐

府 + 月（肉月）
→ 腑

府 + 人
→ 俯

付 + 竹
→ 符

付 + 阜
→ 附

付 + 馬
→ 駙 / 驸

付 + 魚
→ 鮒 / 鲋

ゲーム的に綺麗な長いチェインの一つ。


============================================================
8. 「伐」「伏」など
============================================================

人 + 戈
→ 伐
古字では人の首元に戈を当てる構成。
攻撃系の文字として非常に使いやすい。

伐 + 竹 → 筏
伐 + 門 → 閥 / 阀
伐 + 土 → 垡


人 + 犬
→ 伏
人が伏している姿を表す系統。

伏 + 艹 → 茯
伏 + 衤 → 袱
伏 + 氵 → 洑


============================================================
9. 文字の「意味」が能力
============================================================

単純に
ATK +20%
HP +30%
だけで終わらせない。

文字の意味そのものを戦闘ルールにする。

例:

休
→ 静止・休息・回復

化
→ 変身・属性変換・他レシピへの派生

花
→ 開花・繁殖・範囲展開・花粉

付
→ 能力を他ユニットへ付与

府
→ 拠点・範囲内の味方を統率

腐
→ 腐敗・死体や敵をDoTエリア化

林
→ 木系ユニットの数が増えるほど効果増幅

森
→ 林の上位、召喚・遮蔽・大量生成

焚
→ 林などを燃料にして大火力

禁
→ 敵能力の封印・禁止

明
→ 暗闇解除・透明敵看破・弱点表示

炎
→ 延焼

間
→ 距離・空間を操作

聞
→ 画面外の敵感知、攻撃予兆を可視化


設計原則:

漢字の意味 = WHAT
「何をする能力か」

漢字の構造 = HOW
「どう発動・どう見えるか」


============================================================
10. HP = 構成要素
============================================================

通常の数値HPバーを主役にしない。

文字そのものの構造をHPにする。

例:

林 = 木 + 木

林
↓ 1構成破壊
木
↓
撃破


森 = 木 + 木 + 木

森
↓
林
↓
木
↓
撃破


重要:
攻撃で構成要素が1つ壊れる。

休 = 人 + 木 の場合:

人部分を壊す
→ 木になる

木部分を壊す
→ 人になる

つまり
「文字の部位破壊」。


============================================================
11. 再帰分解
============================================================

文字を再帰的な構成ツリーとして扱う。

例:

花
├ 艹
└ 化
   ├ 人
   └ 反転人

攻撃で
花 → 化 → 人
のように、
漢字の成立を逆再生して倒せる。

データの使い方:

上向きに辿る
= 合体・進化

下向きに辿る
= 被ダメージ・分解

同じ構造DBを両方に使う。


============================================================
12. HPとSIZEは分ける
============================================================

HP:
残っている構成要素・分解階層

SIZE:
文字全体の構造量 / 複雑さ

例:

木
HP 1
小型

林
HP 2
中型

森
HP 3
大型

鬱
超複雑
超大型ボス級

画面いっぱいに巨大な「鬱」が出て、
タイプするたびにパーツが剥がれ、
最後に小さな構成文字へ崩壊する。

SNS映えを強く意識する。


============================================================
13. タイピング入力
============================================================

日本語モード:
原則として「訓読み / 意味読み」を優先。

例:
人 = ひと
木 = き
火 = ひ
水 = みず
山 = やま
川 = かわ
花 = はな
休 = やすむ
化 = ばける / かわる

匕はゲーム上なら
「さじ」
のような訓・意味読みを優先。

ただし中国固有字など、
自然な日本語訓読みが存在しない場合は
「意味読み」を割り当てる。

つまり厳密には:
全漢字に「ゲーム用代表意味読み」を1つ持たせる。


英語モード:
意味に対応する英単語。

火 → fire
水 → water
山 → mountain
花 → flower
休 → rest


中国語モード:
必要ならピンイン入力も将来対応。
中国語話者は形声文字の音符から
未知の合成先を予測できる。


============================================================
14. 熟語システム
============================================================

一文字の合体だけで終わらない。

ゲーム後半では、
完成した漢字同士を並べて「熟語」にする。

重要:
熟語では
文字の「合体」ではなく
「語順」が意味を作る。

例:

火 + 山
→ 火山
→ volcano

これは日本語・中国語の両方で
「volcano」の意味として通じる。

逆順の

山 + 火

は中国語では
山火 = 山火事 / wildfire
の意味になり得る。

つまり:

火 + 山 → 火山 = volcano
山 + 火 → 山火 = wildfire

同じ二文字でも順序で能力が変わる。
これはゲームシステムとしてかなり重要。


他の熟語候補:

山 + 水
→ 山水
landscape / mountains and rivers

火 + 花
→ 火花
spark

大 + 火
→ 大火
large fire / conflagration

火 + 力
→ 火力
firepower / thermal power

水 + 火
→ 水火
water and fire / 相克するもの

※熟語は「実際に使われる語」を辞書DBで確認して採用する。
※無理に二文字を組み合わせて熟語を捏造しない。


============================================================
15. 熟語のゲーム性能
============================================================

単漢字:
基本能力

熟語:
能力同士を組み合わせる上位スキル

例:

火
→ 炎上 / 発火

山
→ 壁 / 地形

火山
→ 地面から噴火
   溶岩エリア生成
   山を生成してから爆発

山火
→ 地形を伝って燃え広がる
   wildfire型

火花
→ 高速小弾
   クリティカル・連鎖発火

火力
→ 火属性全体の出力倍率

山水
→ 地形生成 + 水流
   防御 / 制圧


============================================================
16. ボス戦
============================================================

通常戦:
一文字

中盤:
熟語・四字熟語・成句

ボス:
漢詩

ボス戦では巨大な漢詩が
画面に「術式」のように出る。

プレイヤーは
対応する短い英語をタイプして破壊。

重要:
自由英訳判定にはしない。
正解が無数にあるため。

プロトタイプでは
公式の短い英訳を1つ表示し、
それをタイプする方式。

高難度では英訳を隠してもよい。


============================================================
17. 漢詩ボスの演出
============================================================

詩の内容が本当に画面に起こる。

月
→ 巨大な月

霜
→ 地面凍結

山
→ 山が隆起

河
→ 水流

飛流
→ 滝

炎
→ 画面炎上

つまり:

漢詩を読む
↓
詩の世界が現実になる
↓
英語で意味をタイプ
↓
言語によって世界を破壊する

19. 象形文字SVG
============================================================

古代文字はSVGで扱う。

理由:
・パーツを個別に動かせる
・線を伸ばせる
・反転できる
・分解できる
・モーフィングできる
・被弾時に構成要素を壊せる
・甲骨文→金文→小篆→現代漢字の変形が可能

21. データ設計
============================================================

文字を「再帰構造」として保存。

例:

{
  "char": "休",
  "components": [
    {"char": "人"},
    {"char": "木"}
  ],
  "formation_type": "会意",
  "region": ["COMMON"],
  "meaning_ja": "やすむ",
  "meaning_en": "rest",
  "hp": 2,
  "size": 2,
  "ability_id": "REST_CHARGE",
  "confidence": "A"
}


合体レシピには:

result
component_a
component_b
layout
orientation
formation_type
historical_validity
region
source
confidence

を持つ。


熟語には別テーブル:

word
char_1
char_2
language
meaning_ja
meaning_en
ability_id
frequency
verified


============================================================
22. データの信頼度
============================================================

自動字形分解DBは
「候補抽出」に使う。

自動抽出 = 正式レシピ
にしない。

confidence:

A
古文字・字源・辞書で裏付けが強い
→ ゲーム採用

B
構造は明確だが字源・解釈に異説
→ 採用候補

C
現代字体を機械的に分解しただけ
→ 原則不採用

============================================================
24. Claudeへの実装方針
============================================================

最優先:
「遊んだ瞬間に面白いこと」。

漢字DBを完璧にするより先に、
以下をプロトタイプで成立させる。

1. タイピングで敵を攻撃
2. 敵漢字が構成要素へ崩れる
3. 素材文字を拾う
4. 正しい組み合わせで文字が合体
5. 合体時に派手なSVGモーフ/爆発
6. 進化後、意味に沿った能力へ変化
7. 火＋山を並べると「火山」になって噴火
8. 短い漢詩ボスを英語入力で破壊

見た目:
・黒背景ベース
・漢字を主役
・キャラクター絵に逃げない
・文字そのものが生物/武器に見える
・高コントラスト
・一画一画が飛散する
・画面シェイク
・ヒットストップ
・巨大文字
・ズーム
・文字の変形
を惜しまない


============================================================
25. この企画の核
============================================================

合体 = 漢字を作る
被弾 = 漢字を壊す
HP = 構成要素
SIZE = 構造量
能力 = 文字の意味
演出 = 文字の形
熟語 = 文字能力の複合
ボス = 文学

最終的に、

文字
↓
漢字
↓
熟語
↓
成句
↓
漢詩

と、
ゲームが進むほど
「言語の単位そのもの」が巨大化していく。

「漢字を題材にしたタイピングゲーム」ではなく、

文字体系そのものが
敵・味方・HP・スキルツリー・クラフト・ボス攻撃になっている
タイピング・ローグライトを目指す。
